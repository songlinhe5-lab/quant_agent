本模块由三个子包构成统一的基础设施层：
- `backend/bootstrap/lifecycle.py`：通过 FastAPI `asynccontextmanager` 的 `app_lifespan` 集中编排启动阶段（设置 asyncio/AnyIO 线程池上限、注册数据源适配器、初始化 admin 账号、拉起 LLM/ToolRegistry、NAV 快照、OMS 持仓同步、Finnhub WS tick 回灌、FMP 盘后采集、限流告警消费器、数据源健康监控、配额成本监控、探针探测等后台协程），并在关闭阶段收集所有 `asyncio.create_task` 创建的 task，以 `asyncio.wait_for(..., timeout=30.0)` 统一优雅取消，避免僵尸协程。
- `backend/middleware/stack.py`：以 `register_middleware(app)` 按“后注册先执行”顺序挂载请求级超时、响应信封包装、trace_id 注入、可选 pyinstrument 性能分析、基于 Redis 的分级限流（Gateway + API 级别）、慢请求监控；`audit_middleware.py` 提供审计扩展点，仅对 POST/PUT/DELETE 且路径在 `AUDITABLE_OPERATIONS` 中的请求记录审计日志。
- `backend/core/`：横向能力集合——`config.py` 用 Pydantic Settings v2 做 fail-fast 的环境变量校验；`database.py` 暴露同步/异步 SQLAlchemy Engine 与 SessionLocal/AsyncSessionLocal；`redis_client.py` 提供全局 ConnectionPool、`RedisAsyncBatchWriter` 批量写入队列与进程内 L1 Cache；其余文件（`circuit_breaker*`、`cache_manager`、`encryption`、`error_codes`、`exception_handlers`、`metrics`、`otel_config`、`structlog_config`、`request_timeout`、`response`、`retry_utils`、`security`、`stream_utils`、`ticker_format`、`utils`、`yahoo_news`、`alert_models`、`datalake_models`、`embeddings`、`graceful_executor`、`cpu_pool`、`openapi_schema`）为共享工具与领域模型。
依赖方向：bootstrap → core（数据库/Redis/安全/模型）→ services/workers；middleware 仅依赖 core 暴露的错误码、OTEL trace、Redis 与 structlog 上下文变量，不反向依赖业务服务。
