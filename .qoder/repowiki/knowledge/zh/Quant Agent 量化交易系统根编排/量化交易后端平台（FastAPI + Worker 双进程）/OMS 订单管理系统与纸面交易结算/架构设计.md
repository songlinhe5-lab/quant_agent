模块按职责划分为三层：
- 服务层（services）：`OmsService` 负责订单持久化到 PostgreSQL（Order/TradeLog）、通过 Redis Hash/List 缓存活动挂单并以 PubSub 广播；`PaperLedgerService` 以 `paper_fills` 为不可变流水账本，维护 `paper_positions` 投影并支持 `rebuild_positions` / `reconcile` 对账；`StrategyVersionService` 提供策略代码版本保存、查询与恢复，基于 SHA256 code_hash 实现幂等。
- 运行期 workers（workers/oms）：`AlgoEngine` 管理 TWAP/VWAP/ICEBERG/POV/IS 五种算法拆单任务，每个任务以 `asyncio.Task` 驱动，状态写入 Redis Hash (`quant:oms:algo:active`) 并归档至 List (`quant:oms:algo:history`)，通过 `_simulate_fill` 在 SANDBOX/LIVE 模式间切换，LIVE 时经 `data_source_router.fetch_futu('PLACE_ORDER')` 下单；`BotRuntimeManager` 动态加载 `strategies/live/*.py` 中的策略类，用 `asyncio.Event` 控制暂停/恢复，通过 psutil 采集 CPU/MEM 并写 Redis Hash，日志落盘 Redis List + PubSub。
- 守护进程（workers/paper）：`PaperSettlementDaemon` 每 5 分钟轮询，依据基准标的 K_DAY 判断交易日，盘后逐组合计算 NAV 写入 `paper_nav_daily`，盘中每 5 分钟写 Redis 环形 List 288 点，支持补结算（≤7 天）与周度对账，并通过 TE 漂移检测触发告警。
依赖方向：workers → services → core.models / core.redis_client / datasource.router，服务层不反向依赖 workers。
