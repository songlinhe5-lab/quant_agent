模块按执行模式划分为四个并列驱动：
- `backtest.py` 中的 `BacktestDriver` + `BacktestContext`：基于 `SimClock` 逐 bar 推进，主循环顺序为「撮合挂单/止损 → 调用 `strategy.on_bar` → 分发成交回报」，并通过 `RunManifest` 绑定 code_hash / seed 实现可复现。
- `live.py` 中的 `LiveDriver` + `LiveContext` + `TickAccumulator`：异步主循环订阅 Redis Pub/Sub (`quant:quotes:stream`) 获取 tick，聚合为 K 线后通过 `asyncio.to_thread` 隔离执行策略；行情缺失时降级轮询 `futu_service.get_quote()`，支持 `paper/live` 两种模式，paper 模式复用 `SimBroker` 经 `ExecutionGateway(SimBrokerExecutor)` 注入。
- `vector.py` 中的 `VectorExecutor`：当策略实现 `signals()` 且 `is_vectorizable()` 为真时，直接走 VectorBT 矢量化回测作为同策略的加速路径，并内置无 vectorbt 时的 fallback 简单回测。
- `sim_broker.py` 中的 `SimBroker`：独立于驱动的撮合内核，维护 `PendingOrder` 订单簿、限价单匹配、止损触发、滑点+手续费计算与持仓/现金状态，被 BacktestDriver 和 LiveDriver(paper) 共同复用。
依赖方向单向向外：各 Context 仅依赖 `backend.engine.context.BaseContext`、`backend.engine.contracts` 与 `backend.engine.strategy.Strategy` 抽象；对外部服务（Redis、KlineCacheEngine、MarketSession、PointInTimeStore、SurvivorshipBiasTracker）采用函数内 import 延迟加载，避免启动期耦合。
