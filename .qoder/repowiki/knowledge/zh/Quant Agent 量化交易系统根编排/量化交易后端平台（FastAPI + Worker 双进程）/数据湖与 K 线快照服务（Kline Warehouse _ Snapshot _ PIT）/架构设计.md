模块按职责划分为四个子层：
- 热层写入：`kline_warehouse.py` 中的 `KlineWarehouse` 以 Parquet 文件形式维护 `data/kline_warehouse/{K_DAY,K_60M}/{ticker}.parquet`，通过富途优先、雅虎兜底的增量拉取策略更新，并在每日凌晨 3:00 触发全量同步后调用 `SnapshotPublisher`。
- 快照层：`snapshot_publisher.py` 将 live 层文件 hardlink/copy 到 `snap_{YYYYMMDD}` 目录，生成含 sha256 指纹的 `manifest.json` 并持久化到 PostgreSQL（`DataSnapshot` 表），同时通过 Redis 键 `quant:datalake:latest_snapshot_id` 暴露最新快照；`snapshot_reader.py` 提供只读 API，优先从 Redis 解析 `latest_published/live`，再落盘读取 Parquet；`snapshot_resolver.py` 封装引用解析逻辑，返回不可变 `SnapshotRef`；`snapshot_retention.py` 实现 T1(0–90d) 全保留/T2(91–365d) 仅月锚点/T3(>365d) tar 归档+删本地的三级生命周期。
- 冷归档层：`object_store.py` 的 `S3ObjectStore` 基于 PyArrow `S3FileSystem` 直接按 Hive 分区 `{period}/{symbol_safe}/year=YYYY/month=MM/part-*.parquet` 写入 R2/S3，未配置时优雅降级为 no-op。
- 财务 PIT 层：`financial_pit.py` 定义 `FinancialDataPoint`/`PITQuery`/`PointInTimeStore`，强制 `announce_date >= period_end_date` 不变量，并通过 `as_of_date` 过滤避免前视偏差。
- 共享常量：`paths.py` 集中定义 `LIVE_ROOT`、`SNAPSHOTS_ROOT`、Redis 键名、`KTYPES_V1` 等路径与锁键约定；`manifest.py` 提供确定性 JSON + sha256 的 manifest 构建与校验纯函数。
依赖方向单向：publisher → manifest/paths → DB/Redis；reader → resolver/paths；retention → paths/DB；cold store 独立于快照层。所有外部依赖（Redis、PostgreSQL、metrics、survivorship bias tracker）均在方法内延迟 import，保证模块可被单元测试无副作用导入。
