模块由三层组成：
- 引擎层（`backend/workers/alert_engine.py`）：`AlertEngine` 作为常驻 worker，启动时从 Redis Hash `quant:alerts:rules` 加载活跃规则，通过 `pubsub.subscribe('quant:quotes:stream')` 消费行情，按 `rule_type` 分流至 `evaluate_price_rule`、`IndicatorEvaluator`（ALERT-05）或 `ExprEvaluator`（ALERT-COND-01），触发后写回规则状态、写入事件列表 `quant:alerts:events`（LRU 1000 条），再经 `AlertDispatcher.dispatch` 推送。
- 调度层（`backend/services/alert/dispatcher.py`）：`AlertDispatcher` 是系统通知唯一出口，内部组合 `PriorityResolver`（severity+source→P0~P3）、`ChannelPlanner`（优先级×用户 channels→实际通道表）、`CooldownGate`（基于 sha256(source,rule_id,ticker,severity) 的指纹 + Redis TTL 做通道级冷却，in_app 豁免）、`RetryQueue`（按优先级退避重试并落 DLQ `quant:alerts:dlq`）。`dispatch` 对 P0/P1/P2 并行投递，P3 串行且 in_app 成功后抑制外部通道。
- 适配器层（`backend/services/alert_adapters/`）：每个通道实现 `ChannelAdapter` Protocol（`channel`/`enabled`/`send(event,priority)`），包括 `FeishuAdapter`（Webhook + HMAC 签名，P0/P1 卡片消息）、`TelegramAdapter`（Bot API sendMessage，P3 静默）、`InAppAdapter`（Redis PubSub 发布到 `quant:alerts:push`，前端 WebSocket 订阅）。
- 辅助组件：`expr_evaluator.py` 提供与前端 TS 引擎语义 1:1 对齐的自由布尔表达式求值器（递归下降解析 + numpy 矢量化指标 MA/EMA/RSI/MACD/KDJ/BOLL/REF/CROSS/HHV/LLV），维护每 ticker 滚动 K 线缓冲；`notification.py` 的 `NotificationService` 是 dispatcher 的薄包装，保留旧 `send_alert(message)` 接口向后兼容。
依赖方向单向：engine → dispatcher → adapters，adapter 不反向引用 engine。
