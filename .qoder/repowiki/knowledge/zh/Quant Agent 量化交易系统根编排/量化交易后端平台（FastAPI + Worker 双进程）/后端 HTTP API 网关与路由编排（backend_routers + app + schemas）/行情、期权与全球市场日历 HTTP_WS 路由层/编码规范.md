- 所有 HTTP 响应采用 BE-13 方案 B 的扁平 payload（直接展开 `facade_res.data` 并附带 `source`/`degraded`/`latency_ms`），交由中间件统一包装为 `{code,msg,data,ts}` 信封。
- 富途标的统一通过 `_is_futu_ticker` 判定后走 `data_source_router.fetch_futu` 单独通道，非富途标的走 Facade 统一选源，形成清晰的双通道路由模式。
- 对外部数据源调用采用 try/except 捕获后记录 `logger.warning` 并返回结构化错误字典或抛出 `HTTPException`，避免异常向上冒泡导致 500。
- 需要并发拉取多个标的时，使用 `asyncio.gather` 并行请求并在失败时优雅降级为空列表或占位 tile，保证整体响应可用。
- 易热点缓存键（如 `calendars_snapshot`、`yf_macro_cache_*`）配合进程内 `asyncio.Lock` 池做双重保护，防止缓存击穿引发雪崩。
- 对第三方 API（Finnhub）在限流退避期内通过 `rate_limit_registry.get_throttler(...).should_throttle()` 快速返回 `status=degraded`，成功则调用 `on_success()` 恢复。
