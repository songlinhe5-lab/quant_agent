本模块由三个独立的 FastAPI `APIRouter` 组成，分别挂载到不同 URL 前缀，职责清晰分离：
- `datasource.py`：以 `/datasource` 为前缀，核心依赖 `backend.services.datasource` 中的 `rate_limit_registry`、`datasource_registry`、`call_metrics`，实现限流频率分析（`/{name}/rate-limit-analysis`）、实时退避状态（`/{name}/rate-limit-status`）、全局限流总览（`/rate-limit-overview`）、Finnhub 专用健康检查（`/finnhub/health`）、统一健康看板（`/health-overview`、`/{name}/health`、`/router/health`）、延迟分布/错误率趋势/限流热力图/可用性时间线等监控指标接口，以及带并发控制（全局锁 + per-source 锁 + 信号量）的主动链路探测（`POST /{name}/test-link`），并通过 WebSocket `/ws/health` 推送 STALE 告警。
- `datalake.py`：以 `/datalake` 为前缀，基于 SQLAlchemy `Session` 直接操作 `DataSnapshot` 模型，封装 `SnapshotReader`、`SnapshotPublisher`、`SnapshotRetention` 服务，暴露快照列表、最新快照、按 ID 获取详情、重建快照（`/snapshots/rebuild`）和触发保留策略（`/snapshots/retention/run`）。
- `datasource_vote.py`：以 `/datasource-vote` 为前缀，通过 `get_current_user` 鉴权，使用 Redis 持久化投票计数（`ds_vote:count:*`）与用户当日投票去重（`ds_vote:ud:{user}:{date}:{source}`），结合 `datasource_registry` 动态列出已接入源，并维护 `_SOURCE_META`、`_DEVELOPING_SOURCES`、`_VOTING_SOURCES` 三类静态目录用于前端看板展示。
依赖方向单向向下：路由层仅消费 `services.*` 与 `core.*`（数据库、Redis、鉴权），不反向被 services 引用；各 router 之间无相互 import，通过 FastAPI 应用装配时组合挂载。
