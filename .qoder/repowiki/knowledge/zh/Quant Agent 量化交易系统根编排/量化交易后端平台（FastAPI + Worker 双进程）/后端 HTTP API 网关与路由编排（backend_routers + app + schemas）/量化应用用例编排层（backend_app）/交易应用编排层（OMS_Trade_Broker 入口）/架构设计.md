本模块为应用层入口，按职责拆分为三个文件：
- `broker.py`：薄包装，仅暴露 `backend.services.adapters.legacy_broker.broker_gateway` 单例 `BrokerGateway`，作为所有下游券商交互的统一入口。
- `oms_app.py`：OMS 用例编排，实现 Kill Switch 熔断流程——通过 Redis PubSub 广播 `oms:kill_switch` 信号并写入 `oms:status=KILLED`，随后依次调用 `broker.execute_emergency_liquidation()`、`bot_runtime.stop_all_bots()`、`algo_engine.cancel_all()`、`oms_service.mark_all_orders_cancelled(db)`，保证物理清仓、策略停机和订单落库取消的原子性顺序。
- `trade_app.py`：交易下单编排核心，集中处理杠杆偏好读取（Redis `quant:user:{user}:preferences`）、账户资产缓存（带 `asyncio.Lock` 防穿透）、基于 ATR 的动态波动率风控（高波动强制降杠杆至 1x、计算 2×ATR 止损位）、资金敞口校验（`order_value <= total_assets * max_leverage`），再分发到 `broker.place_order/cancel_order/query_order`，最后通过独立 `SessionLocal` 持久化订单到 PostgreSQL 并写入 `TradeLog` 留痕，同时根据 `quant:oms:trading_mode` 或 `FUTU_TRD_ENV` 判断模拟/实盘模式。
依赖方向单向向下：router → app → services/workers/core，app 层不依赖 router，便于单测对 `backend.app.trade_app.<dep>` 进行 patch。
