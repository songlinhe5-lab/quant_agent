模块以 `main.py` 为唯一 HTTP 入口（FastAPI + uvicorn），所有请求经 `verify_hmac` 依赖校验后由 `fetch_data` 路由到对应 worker；worker 采用延迟导入策略（`_WORKER_IMPORTS` 映射表），仅当声明的 `DS_CAPABILITIES` 包含某 source 时才加载对应 `*_worker.py`，从而让同一镜像在不同部署中按需启用能力。

内部代码按职责分层：
- `_internal/` 为完全自包含的复制层，与外部 backend 物理隔离，提供共享基础件（`circuit_breaker`、`graceful_executor`、`redis_client`、`service_registry`、`logger`、`metrics`、`retry_utils`、`error_codes`、`exceptions`）以及各数据源的具体实现（`yfinance/*`、`akshare/*`、`tushare/service.py`、`search/__init__.py` 等）。
- `futu_src/` 是富途 OpenD 专用子系统，`service.FutuService` 作为全局单例聚合 `ConnectionManager`、`CacheManager` 及各 Handler（quote/option_fund/trade/screener/short_selling/push），并通过 `source_router.FutuSourceRouter` 在本地直连模式下转发到 `LocalDataSource`；启动时通过 `watchdog` 守护长连接并持有强引用防止 GC 回收。
- 顶层每个 `*_worker.py`（yfinance_worker、akshare_worker、futu_worker 等）只负责把 HTTP action+params 翻译成对应 `_internal.<source>.service` 的方法调用，并在异常处统一打日志。
- `nodeinfo.py` 构造 `NodeInfo`（含 capabilities、weight、region），配合 `_internal.service_registry.ServiceRegistry` 通过 Redis Hash/ZSet/Set 完成节点注册、心跳、优雅下线与死节点清理，使主服务可基于能力发现本节点。
- 监控面：`/health` 暴露线程水位与 Futu 连接快照，`/metrics` 输出 Prometheus 指标（含独立 registry），`/metrics/circuit` 暴露熔断器状态。
