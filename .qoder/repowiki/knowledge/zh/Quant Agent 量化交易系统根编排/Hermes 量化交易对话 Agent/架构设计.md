模块以 `agent.py` 中的 `HermesAgent`（继承自 `MemoryOperationsMixin`）为核心，通过 `chat`/`chat_stream_async`/`run_cli` 暴露同步、流式与 CLI 三种入口；核心推理由 `_step_loop` 驱动，最大迭代次数固定为 8，并在超限后切换至 `pro_model` 强制总结。
- 工具层：`tools/base.py` 定义 `BaseTool`（含 ticker 归一化、限流感知重试 `rate_limit_aware_request`、L1/L2 双级缓存），各具体工具文件通过 `@register_tool` 装饰器自动注册到 `tool_registry.ToolRegistry`；`tools/__init__.py` 使用 `pkgutil` 动态扫描并导入所有工具模块，实现零配置热插拔。
- 注册与执行：`tool_registry.py` 在构造时实例化所有已注册工具，提供 `get_all_schemas()` 生成 OpenAI function-calling schema，并通过 `AsyncTokenBucket` 做全局速率限制；`execute()` 统一走 `tool_result_cache.ToolResultCache`（Redis Hash，按 tool_name+args_hash 键控，支持 per-tool TTL 与环境覆盖）。
- 记忆与持久化：`memory_ops.py` 抽离出会话加载/保存（Redis 热 + PostgreSQL 冷）、上下文压缩/自愈、TokenGuard 限流熔断、以及结论事实抽取写入知识库等能力，通过 Mixin 注入 Agent。
- 依赖方向：Agent → ToolRegistry → Tools；Tools 通过 `SecureClient`/后端 API URL 访问外部数据源；Agent 通过 Redis/PostgreSQL 读写会话与知识库，整体单向依赖 backend 基础设施。
