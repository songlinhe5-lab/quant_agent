## 1. 整体方案

Quant Agent 后端（FastAPI）采用「集中式错误码 + 分层自定义异常 + 全局异常处理器 + 可观测性中间件」的组合，将业务错误、外部依赖故障和未预期异常统一收敛到一致的 `{code, msg, data, ts[, trace_id]}` JSON 响应格式。

核心思路：
- 所有业务异常继承 `QuantBaseException`，携带 `ErrorCode` 枚举值；编排层使用 `AppError(HTTPException)` 透传 HTTP 状态码。
- `backend/core/exception_handlers.py` 在应用启动时注册 5 个处理器，覆盖 `QuantBaseException` → `HTTPException` → `RequestValidationError` → `AppError` → 兜底 `Exception` 的完整链路。
- 成功响应通过 `backend/core/response.py` 的 `success()` / `error()` 构造，保证 REST API 返回结构一致。
- 对外部依赖（数据源、LLM、第三方 API）提供 `retry_utils`（tenacity 指数退避重试）和 `circuit_breaker`（CLOSED/OPEN/HALF_OPEN 三态熔断），失败路径抛出 `CircuitBreakerOpenError` 等专用异常。
- `AccessLogMiddleware` 记录请求耗时、状态码并 Prometheus 暴露指标，异常分支同样计数为 500 并 `logger.exception` 输出。

## 2. 关键文件与职责

| 文件 | 职责 |
|---|---|

| `backend/core/exceptions.py` | 定义 `QuantBaseException` 基类及认证(1xxx)、请求(2xxx)、基础设施(3xxx) 子类，以及 `AppError`（继承 FastAPI `HTTPException`） |
| `backend/core/exception_handlers.py` | 注册 5 个全局异常处理器，把各类异常统一转为 `{code,msg,data,ts[trace_id]}` JSONResponse |

| `backend/core/circuit_breaker.py` | 单例 `circuit_breaker` 实现 CLOSED/OPEN/HALF_OPEN 状态机，触发时抛 `CircuitBreakerOpenError` |

## 3. 架构与约定

### 3.1 错误码分域
`ErrorCode` 按领域划分：
- `0` = 成功
- `1xxx` = 认证/鉴权（TOKEN_MISSING=1001、TOKEN_EXPIRED=1002、TOKEN_INVALID=1003、PERMISSION_DENIED=1004、HMAC_INVALID=1005）
- `2xxx` = 请求参数/资源（VALIDATION_FAILED=2001、RESOURCE_NOT_FOUND=2002）
- `3xxx` = 外部依赖/基础设施（FUTU_DISCONNECTED=3001、REDIS_UNAVAILABLE=3002、CIRCUIT_BREAKER_OPEN=3003、ALL_SOURCES_FAILED=3004）
- `5xxx` = 内部未知错误（INTERNAL_ERROR=5000）

每个错误码都通过 `ERROR_CODE_TO_HTTP_STATUS` 映射到标准 HTTP 状态码（如 1xxx→401，2001→400，2002→404，3xxx→503，5000→500）。

### 3.2 异常层次
```
Exception
├── QuantBaseException（业务异常基类，带 code/msg/data/trace_id）
│   ├── DataSourceError（兼容 message/source 旧接口）
│   ├── AuthMissingError / TokenExpiredError / TokenInvalidError / PermissionDeniedError / HmacInvalidError
│   ├── ValidationError / ResourceNotFoundError
│   ├── FutuDisconnectedError / RedisUnavailableError / CircuitBreakerOpenError
└── AppError（继承 fastapi.HTTPException，用于编排层直接返回 HTTP 状态码）
```

### 3.3 全局异常处理链
`register_exception_handlers` 按以下顺序注册（FastAPI 按声明顺序匹配第一个）：
1. `QuantBaseException` → `quant_exception_handler`：查 `ERROR_CODE_TO_HTTP_STATUS` 取状态码，返回 `{code,msg,data,ts[trace_id]}`
2. `AppError` → `app_error_handler`：透传 `exc.status_code`，内容同统一格式
3. `HTTPException` → `http_exception_handler`：用 `status_code` 作为 code，`detail` 作为 msg
4. `RequestValidationError` → `validation_exception_handler`：固定 `code=2001`，data 为字段级错误列表
5. `Exception` → `global_exception_handler`：生成 `trace_id`，记录 `logger.error(..., exc_info=True)`，返回 `code=5000`

### 3.4 重试与熔断
- **重试**：`retry_utils.with_global_retry` 使用 tenacity，条件由 `is_retryable_http_error` 判定——包含字符串匹配（"rate limit"/"too many requests"/"finnhub"/"频繁"/"timeout"）、`httpx.RequestError`、`httpx.HTTPStatusError` 且状态码 ∈ {403,429,500,502,503,504}。默认最多 3 次，随机指数退避 1~10s，`reraise=True` 让上层继续处理。
- **熔断**：`circuit_breaker.call/guard` 维护 per-service 状态机，连续失败 ≥ `max_failures`（默认 3，环境变量 `CIRCUIT_BREAKER_MAX_FAILURES`）进入 OPEN，超过 `recovery_timeout`（默认 60s，环境变量 `CIRCUIT_BREAKER_COOLDOWN_S`）转 HALF_OPEN 探测。OPEN 状态下立即抛 `CircuitBreakerOpenError`（code=3003）。限流类错误可通过 `error_classifier` 或 `is_rate_limit_error` 钩子跳过失败计数。

### 3.5 中间件与可观测性
`AccessLogMiddleware` 在 `call_next` 前后计时，无论成功还是异常都记录 Prometheus 计数器 `fastapi_requests_total`（含 http_status 标签）和直方图 `fastapi_requests_duration_seconds`。异常分支强制将状态码记为 500，并用 `logger.exception` 输出堆栈。
外部 HTTP 调用通过 `httpx_log_request` / `httpx_log_response` 拦截，按 host 分类服务名，暴露 `external_api_requests_total` 与 `external_api_request_duration_seconds`，>3s 告警。

## 4. 约定与约束

- **路由层不直接 return HTTPException**：应优先抛 `QuantBaseException` 子类或使用 `response.error(code=ErrorCode.X, msg=...)`，由全局处理器统一格式化。
- **编排层禁止 import fastapi**：`AppError` 继承 `HTTPException` 是为了兼容最小化测试 App，但注释明确要求 `backend.app.*` 模块只 import `AppError`，不直接 import fastapi，以收敛依赖。
- **错误码必须来自 `ErrorCode`**：`response.error` 和异常构造均要求传入 `ErrorCode` 枚举，避免硬编码数字。
- **未捕获异常一律走兜底处理器**：任何未被显式处理的 Python 异常都会落入 `global_exception_handler`，生成 `trace_id` 并记录完整 traceback，确保生产环境不会静默崩溃。
- **重试仅针对可重试错误**：`is_retryable_http_error` 明确限定 429/403/5xx 及网络层异常，普通业务错误不应被吞掉重试。
- **熔断冷却时间不可硬编码**：`circuit_breaker.py` 注释强调“禁止硬编码 60s”，必须通过 `CIRCUIT_BREAKER_COOLDOWN_S` 环境变量配置。
- **验证失败统一为 code=2001**：Pydantic 校验失败经 `validation_exception_handler` 转换为 `code=2001`，data 为字段定位列表，前端可按此统一展示。

## 5. 适用范围

该体系主要覆盖 `backend/` 下的 FastAPI 服务进程；`data_subservice/`（独立 FastAPI 数据节点）与 `hermes_agent/`、`frontend/`、`client/flutter_app/` 各自有独立的错误处理方式，本卡片聚焦后端主服务的统一错误模型。
