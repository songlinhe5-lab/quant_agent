测试按被测模块镜像组织：根目录存放面向 `backend.main`、认证、中间件、全局异常处理等横切能力的单测；`core/`、`routers/`、`services/`、`tools/`、`test_backtest/` 子包分别对应业务域的子模块。所有用例共享 `conftest.py` 提供的统一脚手架：在进程启动时 patch `redis.asyncio.Redis`、SQLAlchemy 引擎创建、Futu/yfinance 外部依赖，并注入 SQLite + 内存 Redis 的假实现；通过 autouse fixture `_reset_circuit_breaker`、`_mock_external_services`、`_dispose_db_engines_on_teardown` 保证测试隔离与资源释放。HTTP 层测试使用 `fastapi.testclient.TestClient` 或按需挂载目标 router 的轻量 FastAPI 实例（如 `test_datasource_router.py`）。契约类测试借助 `cassettes/*.yaml` 录制第三方 API 响应，由 `contract_replay` marker 控制是否回放或重录。架构约束测试（`test_be_arch*.py`）通过静态扫描 `backend/routers` 源码禁止直连具体数据源 SDK，强制路由→port 抽象边界。
