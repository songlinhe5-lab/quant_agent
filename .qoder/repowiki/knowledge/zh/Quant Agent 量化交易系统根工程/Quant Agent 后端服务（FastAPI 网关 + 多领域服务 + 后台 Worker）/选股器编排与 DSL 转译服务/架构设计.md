模块以 `backend/app/screener_app.py` 作为 HTTP 编排层，仅负责请求校验（Pydantic BaseModel）、路由映射、鉴权注入与对外异常转换（AppError），所有业务逻辑下沉至 `backend/services/screener/service.py` 中的 `ScreenerService` 单例。

- 组合式 Mixin 架构：`ScreenerService` 通过继承 `NlpTranslatorMixin`（`nlp_translator.py`，LLM→DSL 转译 + RAG 向量检索）、`DslParserMixin`（`dsl_parser.py`，JSON→Futu Filter 解析 + 技术形态二次过滤）和 `DaemonMixin`（`daemons.py`，订阅守护进程、每日强势股盘点、知识库 TTL 清理）实现职责解耦。
- 数据模型集中在 `models.py`（`ScreenerFilter`、`ScreenerDecision`）与 `constants.py`（字段白名单、别名映射、技术形态枚举），由 Pydantic 在 before/after 阶段完成模糊纠错、类型强制、互斥冲突检测与中文展示填充。
- 外部依赖方向单向：编排层 → `screener_service` → `market_data` / `kline_warehouse` / `data_source_router` / `llm_service` / `notification_service`；数据库访问通过 `SessionLocal` 线程内执行并 `asyncio.to_thread` 避免阻塞事件循环。
- 缓存与并发控制：DSL 结果按 MD5 写入 Redis 并带随机 Jitter TTL；NLP 转译语义缓存命中后直接秒回；同一 DSL 使用模块级 `_screener_locks` 的 `asyncio.Lock` 做防重入；订阅守护进程用 Redis `SET NX EX` 分布式锁保证多节点幂等执行。
- 包入口 `__init__.py` 仅重导出公开符号以保持旧 import 路径兼容。
