- 通道适配器统一实现 `ChannelAdapter` Protocol，暴露 `channel`、`enabled`、`send(event, priority)` 三个成员，由 `AlertDispatcher.register_adapter` 注册。
- 所有外部 I/O（HTTP/Redis）均包裹 try/except 并记录日志，失败返回 False 交由上层 RetryQueue 处理，避免异常上抛中断主循环。
- 规则评估路径按 `rule_type` 显式分流（价格类 / 指标类 / EXPR 自由表达式），新增规则类型需在分流处显式分支而非隐式判断。
- 冷却去重使用 `hashlib.sha256(f"{source}:{rule_id}:{ticker}:{severity}").hexdigest()[:16]` 生成 fingerprint，并以 Redis key `quant:alerts:cooldown:{channel}:{fingerprint}` 配合 TTL 实现跨进程冷却。
- 优先级策略集中定义于 `ChannelPlanner._DEFAULT_CHANNELS` 与 `_COOLDOWN_TTL` 等映射表中，通过 `NotificationPriority` 枚举索引，新增优先级需同步更新这些映射。
- 表达式求值器与前端 TS 引擎保持语义 1:1 对齐，指标递推公式逐行复刻，并通过测试加载 `frontend/.../expr-golden.json` 做跨语言锁定。
