本模块采用「HTTP 网关 + 业务服务 + 后台 Worker」三态部署：
- 启动装配：main.py 创建 FastAPI 实例，统一挂载 /api/v1 前缀的三十余个 Router，并通过 bootstrap.lifecycle 的 app_lifespan 在启动时初始化数据库扩展（pgvector/pg_trgm）、注册全局 LLM 客户端与服务注册中心；worker.py 则按 DATA_NODE 角色启动采集器守护、ticker/sentiment/screener/paper_settlement/market_review/morning_briefing 等异步任务。
- 横向通信：所有子模块通过 core.database (SQLAlchemy)、core.redis_client (Redis 批量写入队列)、core.service_registry 以及 Redis 行情流/消息总线进行跨进程协作，而非直接 import 耦合。
- 边界契约：engine/contracts 定义策略执行接口，backtest/engine/drivers 实现 live/backtest/vector 三种驱动；services/datasource 通过 DataSourceInterface 协议聚合 AKShare/Finnhub/Tushare/FMP 等多数据源；routers 仅做请求路由与参数校验，具体用例委派给 services/* 与 domain/*。
- 可观测与治理：core.middleware.stack 统一注入审计中间件，core.exception_handlers 集中处理异常，core.metrics/otel_config 暴露 Prometheus/OpenTelemetry 指标，alembic/versions 管理 DB 迁移。
- 运行形态：主进程负责 HTTP 请求，worker 进程负责数据采集、CEP、告警推送、纸面结算等长驻任务，两者共享同一份配置与 Redis/DB。
