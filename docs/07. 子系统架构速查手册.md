## 子系统一：前端 Web Terminal

**详细架构**：`docs/04. 前端架构与零GC渲染.md`（V4.0 · SSOT）

| 属性 | 描述 |
|:---|:---|
| **技术栈** | React 18 + Vite SPA + TypeScript strict + Tailwind CSS |
| **路由** | React Router v6（`App.tsx` 声明式路由 + `DashboardLayout` 壳） |
| **状态管理** | Zustand（低频业务状态）+ `useRef`/TypedArray（高频 Tick） |
| **渲染引擎** | Lightweight-Charts（K 线）/ PixiJS（盘口）/ AG Grid（大表）/ ECharts（分析）分级 |
| **通信协议** | WebSocket（行情）+ SSE（AI 流）+ `@/lib/api-client` fetch（REST） |
| **部署方式** | Cloudflare Pages（`quant.stephenhe.com`）；`VITE_API_BASE_URL` 指向 `https://api.quant.stephenhe.com/api/v1` |

**入口文件**：`frontend/src/main.tsx → AuthProvider → App.tsx`
**页面模块**：`frontend/src/features/`（quotes / oms / strategy / paper / research / data-center 等 22 域）
**全局状态**：`frontend/src/stores/`

**核心数据流**：
```
WebSocket 行情 → useRef/TypedArray → 图表 .update() → Canvas 渲染（零 GC）
SSE Agent 流  → ChatStore(Zustand) → React 重渲染  → 打字机效果
REST API      → api-client fetch → 组件 state → React 渲染
```

> 注：旧版 `router/index.tsx` 已于 2026-07-13 清理（`TradingDashboard` 双布局污染一并删除），路由唯一入口为 `App.tsx`。

| `backend/workers/` | 长驻后台任务（quote_publisher / oms（含 algo_engine）/ paper / collectors / alert_engine） | 处理 HTTP 请求 |
| `backend/core/` | 基础设施（database/models / redis_client / config / security / cpu_pool） | 写业务逻辑 |
| `backend/schemas/` | Pydantic 请求/响应 Schema | 写业务逻辑 |
| `backend/middleware/` · `backend/adapters/` | 横切中间件 / 遗留契约适配器 | 新增业务逻辑 |

### 数据源三层架构（BE-ARCH-06）

| 层 | 目录 / 文件 | 职责 | 红线 |
|:---|:---|:---|:---|
| 业务聚合 Facade | `backend/services/datasource/business/` | 业务语义接口、源选择策略、多源融合、Stale 检测、归一化 | 禁止直连数据源库 / 直发外部 HTTP |
| 统一服务面 | `services/datasource/source_registry.py` (`DataSourceRegistry`) + `router.py` (`DataSourceRouter`) | 限流、熔断、HTTP 路由、failover | 禁止写业务语义 |
| 薄适配器 | `services/datasource/adapters/*.py` (`DataSourceInterface`) | 链接底层、基础检测、协议对齐 | 禁止写业务策略 |

**依赖物理隔离红线**：主服务 `requirements.txt` 零第三方数据源 SDK；数据调用一律 `DataSourceRouter` → 子服务 HTTP（详见 `docs/03 §4.4` / `docs/14`）。

**API 端点速查**：见 `docs/10. API接口规范.md` 及 `docs/openapi.json`

## 子系统三：Hermes Agent 推理引擎

**详细架构**：`prompts/system/HERMES.md`（运行时人设）+ `docs/22`（工具链稳定性）+ `docs/03 §3.3`（边界）

| 属性 | 描述 |
|:---|:---|
| **框架** | 自研 ReAct 引擎：Plan → Tool → Verify → Output |
| **工具数量** | 33 个标准工具（`hermes_agent/tools/*_tool.py`） |
| **LLM** | 主模型 `LLM_MODEL` 环境变量（当前 deepseek-v4-flash）；降级链可配 |
| **输出流** | SSE（`/sse/v1/*`）逐 token 推送；禁止用 WS 传思维链 |
| **能力扩展** | approval（人工审批）· subagent · memory_ops · tool_result_cache · retry_classifier · rollout_storage |
| **RAG 存储** | pgvector（PostgreSQL 向量扩展） |

**Tool 调用约定**：
- Tool 函数统一接受 `str` 参数，返回 `dict`；经 `tool_registry.py` 注册
- 每个 Tool 必须有对应 `hermes_agent/tests/test_xxx_tool.py`
- Tool 内部不调用其他 Tool（防循环依赖）；失败抛 `ToolExecutionError`（含错误码）
- **数字类输出必须来自 Tool，失败须明示，禁止估计值；同一 Tool 连续失败 3 次必须熔断**

**新增 Tool 流程**：
1. `hermes_agent/tools/` 下创建 `xxx_tool.py`
2. `tool_registry.py` 注册
3. `hermes_agent/tests/` 创建测试
4. Tool 只打内网后端 `/internal/v1/*`（HMAC），禁止直连外部数据源

## 子系统边界规则（Boundary Rules）

> 跨子系统的数据流必须经过明确的接口，不允许"内部捷径"。

```
✅ 允许的调用方向：
  Frontend / Flutter → Backend Gateway（HTTP / WebSocket / SSE）
  Hermes Agent       → Backend Gateway（/internal/v1/* HMAC）
  Backend（routers → app → services → domain）→ Engine / Workers
  Backend Gateway    → data_subservice（DataSourceRouter HTTP + HMAC）
  Workers            → Redis（数据总线）← Backend Gateway

❌ 禁止的调用方向：
  Frontend / Flutter → External APIs 直连（Futu / YFinance 等）
  Hermes Tool        → External APIs 直连
  主服务任何层        → 数据源 SDK（futu-api/yfinance/akshare/tushare 等）
  data_subservice    → 业务逻辑 / import backend
  研究域             → ExecutionGateway 下单 / live 行情出统计结论
  Router             → External APIs 直连（必须经 Service/Facade）
```
