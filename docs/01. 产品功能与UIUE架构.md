## 一、产品定位与信息架构

### 1.1 产品定位

QuantEdge 是一款**面向单兵量化交易者的全栈投研终端**，核心价值主张：

1. **AI 深度集成**——从选股到策略生成到风险研判，AI 贯穿全工作流
2. **毫秒级实时**——WebSocket 行情 + Canvas/WebGL 渲染，盯盘无延迟
3. **可信回测**——PIT 财务 + 幸存者偏差 + **数据快照版本化**，回测结果可复现（`DQ-*` · `docs/19`）
4. **沙箱 → 纸面 → 实盘**——单次沙箱推演 → 常驻纸面组合验证 → 版本化部署实盘（`PT-*` · `docs/17`）
5. **三端覆盖**——Web 重型工作台 + Flutter 移动端随身监控（告警推送为核心场景）

### 1.4 设计原则

| 原则 | 说明 |
|:---|:---|
| **上下文持续** | 模块切换不卸载组件（Keep-Alive），K 线缩放、策略代码不丢失 |
| **数据密度分级** | 极密（盘口 11px mono）/ 密（AG Grid 12px）/ 标准（卡片 14px）/ 稀疏（标题 16px） |
| **键盘优先** | Cmd+K 命令面板、B/S 快速下单、Cmd+1~9 模块切换 |
| **三模式安全常驻** | SANDBOX / PAPER / LIVE 横幅永远可见（§1.6）；破坏性操作双重确认 |
| **STALE 感知** | WS 断连时数据区域自动叠加 STALE 遮罩，不展示过期数据 |
| **可复现优先** | 正式回测默认绑定数据快照 + 策略版本（`docs/19` · `docs/16`），非 live 数据 |

### 1.6 运行模式规范（V2.2 新增 · 三模式）

| 模式 | 语义 | 顶栏标识 | 下单/撮合 | 典型场景 |
|:---|:---|:---|:---|:---|
| **SANDBOX** | 单次推演，无持久账本 | 🟡 橙色横幅 | Futu 模拟盘或纯内存（见 OMS 实现） | 策略 IDE 点「运行沙箱」 |
| **PAPER** | 常驻纸面组合，虚拟账本 SSOT | 🟠 橙色横幅 + 「PAPER」 | SimBroker 记账（docs/17） | Paper Bot 长期运行 |
| **LIVE** | 真实资金 | 🔴 红色脉冲横幅，不可关闭 | Futu 实盘 + `REAL_TRADE_EXECUTE` 双锁 | 生产交易 |

**产品规则**：

- 模式切换仅能在 **Settings** 或 OMS 顶栏（需二次确认）；PAPER ↔ LIVE 切换须展示当前纸面组合摘要（运行天数 / Sharpe / TE · docs/17）
- 用户不可从 SANDBOX 单次回测直接跳 LIVE；必须经过「保存版本 → Paper 或显式风险确认」
- Kill Switch 触发后：全模式冻结下单 UI，P0 告警（docs/18）

### 2.3 核心交互

| 交互 | 触发方式 | 行为 |
|:---|:---|:---|
| 切换标的 | 点击自选列表行 | 主图/盘口/成交明细同步切换 |
| K 线缩放 | 鼠标滚轮 / 双指捏合 | Lightweight-Charts 原生手势 |
| 十字线 | 鼠标悬停 / 长按 | 显示 OHLCV Tooltip |

### 4.2 痛点分析（历史 · 2026-06）

> ⚠️ **V2.2 勘误**：下列痛点针对 2026-06 单文件 `strategy.tsx` 时代。截至 2026-07，三栏骨架已拆分（`features/strategy/` 多文件），**仍待完成**：4 Slice Store、Diff 工作流、PG 版本（docs/16）。

原 `strategy.tsx` 单文件集成了代码编辑、AI 生成、AST 检查、沙箱推演，存在以下缺陷：
1. **视觉拥挤**：AI 对话框、代码区、回测图表挤在同一视口

### 4.4 关键交互路径

## 十六、全球市场日历 (Calendars)（V2.3 新增）

> **设计来源**：对标 [yfinance.com](https://finance.yahoo.com) 顶部 Markets 横向滚动条（左侧类目侧栏 + 右侧无限横向滚动行情卡片，每张卡片含名称/最新价/涨跌额/涨跌幅/迷你 Sparkline）。本节将"全球大类资产行情"与"时间驱动型日程（财经日历 / 财报 / 分红 / IPO / 节假日）"**合并为一站式的"市场日历"总览**——这是 yfinance 行情密度与 Bloomberg 日历深度的杂交产物，单兵量化者最缺的就是这种"扫一眼全球，再点进细节"的工作流。
>
> **关联**：§八 宏观数据中心（边界澄清，本节不替代六象限风险雷达）、`docs/14` 数据源架构、`docs/20` 视觉规范、`docs/04` 零 GC 渲染。

### 16.1 功能定义

**一句话**：以"类目 × 标的"二维网格，呈现全球主要金融市场当下与即将发生的一切——行情快照（日内分钟级）、重要日程（财经/财报/分红/IPO）、交易时段（盘前盘后休市）——**一屏全览，无需切换 Tab**。

**与现有 Macro Hub（§八）的边界**：

| 维度 | Macro Hub（§八） | Calendars（§十六） |
|:---|:---|:---|
| 信息密度 | 低（关键指标 8~12 个 + 雷达图） | **极高**（50+ 标的横向滚动 + 多类目日程） |
| 视图模式 | 仪表盘（Dashboard） | **类目导览（Marketplace）** |
| 主体 | 风险综合判断 | **市场全景** |
| 日程位置 | 右下角小日历表格 | **顶部 Tab 切换：Markets / Earnings / Economic / Dividends / IPOs / Hours** |
| 与时区关系 | 单一显示 | **支持多时区切换**（HKT / UTC / ET / JST 等） |

**复用现有数据**：

### 16.4 数据模型

**新增后端 Schema**（草案）：

```python
class CalendarCategory(str, Enum):
    US_MARKETS = "us_markets"      # 美股大盘 + 期货
    EU_MARKETS = "eu_markets"      # 欧股
    ASIA_MARKETS = "asia_markets"  # 亚股
    CRYPTO = "crypto"              # 加密货币
    RATES = "rates"                # 利率/债券
    COMMODITIES = "commodities"    # 大宗商品
    CURRENCIES = "currencies"      # 外汇
    CUSTOM = "custom"              # 用户自定义

class CalendarTile(BaseModel):
    """单卡片数据契约，对应 yfinance 一个 tick"""
    symbol: str                    # "SPX" / "BTC-USD" / "ES=F"
    display_name: str              # "S&P 500"（中文本地化由前端 i18n）
    yf_ticker: str                 # 真正下发 YFinance 的代码（"^GSPC"）
    price: float                   # 最新价
    change_abs: float              # 涨跌额
    change_pct: float              # 涨跌幅（%）
    sparkline: list[float]         # 最近 60 个点（约 1 小时分钟级）
    updated_at: datetime           # 数据时间戳
    is_stale: bool                 # 距上次更新 > TTL ?
    source: str                    # 数据源: yf / futu / fred / akshare
    category: CalendarCategory

class CalendarSnapshot(BaseModel):
    """类目维度聚合"""
    category: CalendarCategory
    display_name: str              # "US Markets"
    tiles: list[CalendarTile]
    next_session_change: datetime | None  # 该类目下一个开盘/收盘时间
    is_market_open: bool           # 当前是否交易时段

class CalendarsSnapshotResponse(BaseModel):
    """GET /api/v1/calendars/snapshot 完整响应"""
    timezone: str
    server_time: datetime
    categories: list[CalendarSnapshot]
    custom_groups: list[CalendarSnapshot]  # 用户自定义类目
    data_sources_health: dict[str, HealthInfo]  # 透传数据源健康态
```

### 16.5 数据源路由

> **架构约束**（对齐 `docs/14 §10`、AGENTS §10）：**所有数据源必须经 `DataSourceRegistry.fetch`**，禁路由层直连；新增分红/IPO/时段三个端点须先实现 `DataSourceInterface` Protocol。

| 数据 | 优先源 | 备选源 | 刷新频率 | TTL |
|:---|:---|:---|:---|:---|

| 利率/债券 | FRED（DGS10/DGS2/DGS30） | Yahoo `^TNX` | 日级 / 实时混合 | 5min |
| 大宗商品 | Futu（GC/SI/CL 主连） | Yahoo `GC=F/CL=F` | 实时 | 30s |

| 财报日历 | Finnhub | Futu（仅港股） | 每日 | 6h |
| 分红日历 | Futu（港股） + Finnhub（美股） | — | 每日 | 6h |
| IPO 日历 | Finnhub | AKShare | 每日 | 6h |
| 市场时段 | 静态预置 + 夏令时偏移 | — | 季度 | 7d |

**降级与容错**：

- 任一数据源 STALE → 对应卡片角标 ⚠️ STALE（`docs/20 §2` 规范），不影响其他卡片
- 数据源熔断 → 整行类目卡片变灰，类目侧栏图例红点 + 提示"该类目暂不可用，12 秒后重试"
- `colocation`：与现有 macro 端点共用 `_fetch_macro_assets_data` 的 Redis 缓存，TTL 一致

### 17.2 六大升级方向

#### 方向一：期权与波动率曲面（OPTION-01~03）— ✅ 已落地（产品章见 §十九）

- **定位**：将已有的 `OPTION_CHAIN` 工具从「能查到数据」升级为「能看懂波动率结构」
- **核心功能**：
  1. **IV 热力图面板**：行=行权价、列=到期日、单元格色阶（绿=低 IV、红=高 IV），一眼识别 tail risk
  2. **波动率曲面 3D**：ECharts GL 三维曲面图（X=行权价、Y=到期日、Z=IV），叠加 skew + term structure 辅助线
  3. **P/C Ratio 实时面板**：总 PCR + 分到期日 PCR + 20 日历史均值对比 + 标的收盘价副图
- **产品价值**：期权 IV 是市场对未来的真实定价，比后视镜 TA 信号领先 1-2 个交易日

#### 方向二：资金流向增强（FUNDFLOW-01~02）— ✅ 已落地（产品章见 §二十）

- **定位**：将资金流数据从后台接口维度升级为前台决策面板
- **核心功能**：
  1. **三市场资金看板**：A股北向资金（日/周/月净流入 + 行业饼图）、港股南向资金（港股通十大成交榜）、美股大单（Block Trade Tide Chart）
  2. **龙虎榜席位排行**：港股 Broker Queue（买盘最强/卖盘最凶经纪商）+ A股龙虎榜（机构 vs 游资标签）
- **产品价值**：主力资金是行情的燃料，资金面独立于基本面和技术面提供第三者视野

#### 方向三：财报与研报本地 RAG（EARN-02~03）— ✅ EarningsQAPanel 已落地（产品章见 §二十）

- **定位**：让 AI 帮你读财报，而非你自己翻 PDF
- **核心功能**：
  1. **RAG 问答面板**（`EarningsQAPanel`）：上传 PDF / 拉取已入库报告 → 自然语言提问 → AI 回答（带原文引用章节跳转 + 追问链上下文保持）
  2. **语义检索**：自然语言搜索「所有提到 CapEx 上修的公司」，搜索结果高亮相关段落 + 来源报告
- **产品价值**：专业投资者一季报要读 200+ 份 PDF，RAG 将阅读成本降低 90%
- **技术**：复用 `backend/workers/knowledge_base.py` 全局向量库 + `POST /api/v1/rag/chat` 新端点

#### 方向四：情绪量化（SENT-01~02）

- **定位**：市场情绪不是 feel，是可以量化的信号
- **核心功能**：
  1. **市场情绪综合指数**（Fear & Greed Index 风格）：VIX(30%) + P/C Ratio(25%) + Credit Spread(25%) + 新闻 NLP 情绪(20%) → 0~100 仪表盘 + 历史时序
  2. **个股舆情情感时间序列**：每日新闻情感值（-1~+1）折线 + 股价副图对比（情绪是同步/滞后还是领先？）
- **产品价值**：极端恐慌（<20）和极端贪婪（>80）是历史反复验证的反转信号

#### 方向五：决策工具产品形态

- **BRD-01 早报一键生成器**（✅ 已落地，产品章见 §十八）：
  - 一键编排 `get_macro_calendar` + `get_broker_market_data(QUOTE)` + `get_macro_news` + `get_macro_sentiment_history` → LLM 组装
  - 输出严格遵循 `AGENTS.md §7` 早报模板 + 新闻卡片格式 + 多空概率矩阵
  - 定时任务：日盘前 15min 自动推送 + Dashboard 顶部手动触发按钮
- **COND-01 网格搜索结果保存为"策略配方"**：
  - 已完成 `runParamGridSearch` 引擎（PROD-11 追问6）
  - 产品化：保存（命名 + 参数快照 + 回测指标）→ `strategy_recipes` 表 → 配方列表 + 一键对比 + JSON 导出
- **ALERT-COND-01 条件单沙盒**：
  - 条件构建器（指标 + 运算符 + 阈值，支持 AND/OR 组合）→ 沙盒引擎 1min 轮询 → 命中弹通知
  - 目前 OMS 未实装，仅模拟通知；待实盘切换后可直接复用为真条件单

#### 方向六：社区与协作（COMM-01~02）

- **COMM-01 数据源健康度统一看板**（✅ 已落地，`/datasource-health` 路由 + `datasource-health.tsx`）：
  - 卡片矩阵：每个数据源独立卡片（名称/状态/延迟/今日调用量/成功率/限流次数）
  - 实时数据来源：`/api/v1/datasource/{name}/health` + Redis `rate_limit_registry`
  - 报警：STALE > 5min → 卡片变红 + WS 推送
- **COMM-02 数据源贡献投票**（P3 探索）：
  - 展示「已接入/开发中/社区投票中」三类源，用户可投票影响接入优先级

## 二十六、执行质量分析（TCA）（V2.5 新增规划）

> **对标**：Bloomberg EMSX / QuantConnect 执行分析；业界核心命题「回测收益 ≠ 实盘收益」的归因闭环。
> **架构指针**：[`docs/25` 执行质量分析架构设计](./25.%20执行质量分析架构设计.md) · 任务 `TCA-01~04`（已录入 `TODO-engine.md`）

### 26.1 功能定义

以三层账本（回测成交 / 纸面 `paper_fills` / 实盘 OMS 成交）同源对齐，量化回答：**策略想法到真实成交之间损失了多少、损失在哪里**。

| 指标族 | 内容 |
|:---|:---|
| 实施缺口 (IS) | 信号价 → 决策价 → 成交价的三段滑点分解 |
| 时机成本/机会成本 | 未成交部分的潜在损益 |
| 回测-纸面-实盘偏差 | 同一 `strategy_version_id` 三层 NAV 曲线叠加 + 归因（滑点模型偏差/延迟/拒单） |
| 算法委托评估 | TWAP/VWAP 执行质量（对接 §6.4 算法委托） |

### 26.2 布局设计（OMS 新 Tab）

```
┌──────────────────────────────────────────────────┐
│ 执行质量        [策略: momentum_v3 ▾] [近 30 日 ▾]    │
├────────────────────┬─────────────────────────────┤
│ 三层 NAV 叠加曲线   │ 滑点分布直方图（买入/卖出分列）   │
│ 回测/纸面/实盘      │ 中位滑点 + 尾部预警（>3σ 标红）   │
├────────────────────┼─────────────────────────────┤
│ 逐笔偏差表 (AG Grid)：信号时刻/信号价/成交价/IS/归因标签 │
└──────────────────────────────────────────────────┘
```

### 26.3 产品规则与验收

- 数据源只用真实成交与真实行情快照，禁止模拟滑点凑数；无实盘数据时只显示回测-纸面两层并明示（对齐 §4 红线）
- 滑点统计反向哺回测参数区（§5.0 滑点模型下拉）：实测中位滑点可一键设为默认，形成「实测 → 回测参数」闭环（差异化壁垒）
- 验收：三层成交对齐率 ≥ 99%（按 `strategy_version_id` + 标的 + 信号时刻）；偏差表可导出 CSV；逐笔计算延迟 < 200ms/笔
- 依赖：§9.5 纸面账本（PT-01）、OMS 成交记录、回测成交明细（BT）；任务拆分见 docs/25
