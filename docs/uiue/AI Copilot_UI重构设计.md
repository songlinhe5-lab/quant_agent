# AI Copilot · UI/UE 重构设计

> 版本 v1.0 · 2026-08-21 · 仅方案文档与 Figma 导入稿,不改仓库代码
> 形态决策:**一体两态** —— 保留全局浮动抽屉(轻量随问随答) + 左导航新增「投研」工作台(深度投研会与资产沉淀),两形态共享同一会话状态。

---

## 1. 决策摘要:浮动窗口还是左 tab?

**答案:都要,但分工明确。**

用户的问题是一个二选一,但代码事实与业界演进都指向第三条路——**双形态**:

**代码事实(为什么要拆):**

1. 现在的 Copilot 是全局右侧浮动抽屉(`features/copilot/global-copilot-drawer.tsx:206-214`,fixed 定位,宽 360–800px,默认 520px),内部已经塞了「对话 / AI 投研团队」两个 tab(`global-copilot-drawer.tsx:84-88`)。投研会 13 位专家 × 多轮辩论的卡片网格被压缩在 520px 里,截图可见专家卡文字截断、阵营对比无从展开。
2. 系统同时存在第三种形态——场景模式的 AI 全屏(`dashboard-layout.tsx:213-216` 渲染 `<FullscreenCopilot />`),但它与抽屉**各持一个 ChatProvider 实例,会话状态互不同步**(见 §2-P0-1)。也就是说"全屏工作台"这个需求已经用场景模式曲线救国过一次了,只是没有成为正式导航入口。
3. `/copilot` 路由是空壳(`features/trading/copilot.tsx:10-15`,仅 `openCopilot()` + 一句"AI 副驾已迁移至全局右侧抽屉"),左导航历史上存在过 AI 入口,迁移时只留了跳转。恢复一个正式入口的成本极低。

**业界事实(为什么是双形态):**

| 产品 | 演进路径 | 收敛形态 |
|:---|:---|:---|
| Microsoft Copilot (Win11/M365) | 两年内 6 次重构:任务栏弹窗 → 独立 App → 右侧 dock → 侧边栏回归 | 常驻侧边伴侣 + M365 Chat 独立入口,轻答与深做分离 |
| GitHub Copilot (VS Code) | 侧边聊天面板 → Activity Bar 独立 Copilot 视图 + 次级侧栏 + Agent 全屏 | 停靠面板管随问随答,独立视图管多会话与 Agent 深任务 |
| Bloomberg 终端 | 一切皆 panel/function,命令式唤起 | 停靠面板哲学,不做悬浮孤岛 |
| Hebbia / Harvey(垂直投研/法律 AI) | 全屏工作区 + 成果(artifact)库 | 深度研究必须有专属页面与资产沉淀 |
| Cursor | 右侧可调宽 chat pane + 背景 Agent | 伴侣面板 + 后台深任务并行 |

**结论**:轻量、跨页、上下文感知的快问快答 → 留在浮动抽屉;多会话管理、多智能体投研会、研报资产沉淀 → 进左导航「投研」页。这正是本系统两类负载(盯盘时的即时一问 vs 17 专家多轮辩论)的天然分界线。

**投研会定位**:旗舰场景,升级为「投研」页核心的**独立辩论室**——阵营对抗布局 + 轮次时间线 + 首席收敛报告,历史可持久化检索(后端落库为待建项,见 §8)。

- 行情页独立的「解盘副驾」AI-02(`co-pilot-panel.tsx`,订阅 `/ai/stream`)**不在本次范围**,保持现状。

## 4. 形态 A:全局浮动 Copilot(轻量)

### 4.1 定位与触发

| 项 | 规格 |
|:---|:---|
| 定位 | 跨页随问随答的伴侣面板:盯盘时的一问、右键标的快问、当前页上下文的即时追问 |
| 挂载 | 保持 fixed 右缘浮层,不挤压主内容(现状保留) |
| 宽度 | 360–800px 可拖,默认 480px(从 520 下调,给右列留白;上限 800 保留) |
| 触发 | ① ⌘/Ctrl+⇧A 全局热键 ② 右缘把手按钮(盯盘模式 aiRole=hidden 时隐藏,现状保留)③ 右键"问 AI 分析"(统一走 `quant_copilot_invoke`)④ 各页面"问 Copilot"文字链 |
| 折叠语义 | width→0,连接与状态保留(现状语义不变,改由 store 承载) |

### 4.2 结构(自上而下)

**A1 头部条**(40px)
- 左:会话标题(单行截断;新会话显示"新对话")
- 右三按钮:历史(打开会话列表浮层,只显示最近 8 条 + "全部 → 投研页")、展开(→ 投研页同一会话,`/research?session={id}`)、收起
- 流式进行中,「展开」按钮显示脉冲点,提示"流不会中断"

**A2 上下文 chip 行**(有上下文才出现)
- 📎 chip:`上下文 · {kind标题}`(如"上下文 · K线 MSFT 5m"),右侧 × 可移除
- 保留现状交互(`global-copilot-drawer.tsx:103-120`),补充 kind 图标:kline=蜡烛、risk=盾、screener=漏斗、analysis=星

**A3 消息流**(共享组件 `MessageStream`,与投研页同实例)
- 空会话:紧凑欢迎区——一句话定位 + 4 个快捷指令 chip(来自统一配置源,见 P1-5):个股深度研判 / 对标分析 / 财务异常检测 / 目标价评估(即现 STOCK_QUICK_COMMANDS,保留"点击预填输入框并选中 {输入标的} 占位符"交互)
- 用户消息:右对齐气泡
- 助手消息:左对齐,内嵌**思维链四阶段进度器**(§6.1)与工具折叠块
- 图表注解(`chart_annotation`)渲染为缩略卡片:点击 → 若有 symbol 跳个股工作台,无 symbol 则禁用并标注"无关联标的"
- 策略代码块(`strategy_code`)渲染为 SANDBOX 卡片:深色代码预览 + 徽章「SANDBOX · 未实盘」+ 按钮"去策略研发工作台"(深链携带代码块 id)。LIVE 文案永不出现在未过 `REAL_TRADE_EXECUTE` 闸门之前
- 达到迭代上限的总结:卡片顶部 amber 提示条「已达 8 步推理上限,以下为降级模型兜底总结」(P1-4)

**A4 输入区**
- 单行自动增高 textarea(1→4 行),Enter 发送 / ⇧Enter 换行
- 输入框上方:快捷 chips 横向滚动条(空会话时显示完整四件套;有消息后收起为 "+" 按钮唤出)
- 左下:上下文 chip(若当前页有可附加上下文且尚未附加,显示虚线 "+ 附加本页上下文")
- **撤下图片/PDF 按钮**(P0-3),原位置改放上下文入口
- 发送按钮:流式中变为 ■ 停止(abort 现有流,保留已产出内容)

### 4.3 删除项

- 「对话 / AI 投研团队」双 tab 结构:投研会整体迁往投研页,抽屉只留对话。抽屉头部不再出现 tab 切换。
- 图片/PDF 上传三入口(P0-3)。
- 会话侧栏内的模拟恐惧贪婪指数(P1-2),侧栏本身保留在投研页,见 §5.2。

### 5.4 B2-投研会·辩论室(旗舰)

三态界面:**组局 → 辩论 → 收敛**。

**① 组局态(Proposition Composer)**

自上而下四组,居中 720px:

1. **投研命题**:textarea(3 行起),占位符示例"比亚迪 2026 年估值是否已透支?";右下角字数计数与"从当前持仓生成"辅助按钮(调 useCopilotContextStore 的 risk summary 预填,上下文缺失时禁用并标注原因)
2. **投研场景**:4 张单选卡(金融投研 / 完整投决会 / 交易决策 / 代码审查),每卡一句话说明 + 推荐阵容徽标。场景数据来源后端 `GET /expert-team/scenarios`(端点已存在,替代前端静态镜像 `expert-roster.ts:66-71`——静态镜像保留为离线兜底,须标注兜底角标)
3. **出战阵容**:13 位金融域角色网格(多选,默认按场景推荐勾选;代码域 4 人仅在代码审查场景出现)。每卡:角色名 + 一句话立场倾向(如风控官·天然空头) + 勾选态。右上"清空 / 恢复推荐"

```
└──────────────────────────────────────┴─────────────────┘
```

- 专家卡阵营色:看多 `text-emerald-400` 边、看空 `text-red-400` 边、中性 `text-gray-500`(与系统涨跌色一致:多=涨色=emerald,空=跌色=red)
- `round_complete` 事件:时间线该轮打勾,观点流插入轮分隔条"第 N 轮结束 · 共识度 X%"(共识度=立场不再变化的人数占比,前端可从意见序列计算,标注口径)
- `expert_opinion` 流式到达:卡片从 skeleton 翻转为内容;同一专家新一轮观点追加为新卡并连线上一轮(观点演化轨迹)
- 断流处置:SSE 中断 → 辩论态顶部 amber 横幅「连接中断 · 已保留 N 条观点 · 重试」,不用假数据续写
- 停止按钮:头部 ■ 中止,落「已停止」态(保留已产出,明示未完成)

**③ 收敛态(Chief Report)**

- 首席投资官报告卡(居中 760px):
  - **概率仪表**:bullish_probability(0–100)半环仪表,指针色随档位:≥60 emerald / 40–60 gray / <40 red;中心数字 + 档位文案(偏多/中性/偏空)
  - 结论摘要段落(流式渲染)
  - **关键分歧保留区**:列出最终轮仍对立观点(多/空两列对照)——禁止把辩论压成单一口径
  - 元信息行:参与专家数 · 轮数 · 总耗时 · 模型
- 操作行:`存入资产库` / `导出 Markdown` / `调整阵容重跑`(回填组局态) / `追问首席`(以该会话继续对话模式)

### 5.5 B2-资产库

- 卡片列表:类型图标(📄 对话导出 / ⚖️ 首席报告)+ 标题 + 来源会话 + 日期;搜索框;点开为只读预览(Markdown 渲染)
- 数据来源:对话导出(现 `chat-context.tsx:192-210` 能力,从"下载文件"升级为"同时存档")+ 首席报告存档;后端持久化待建期间,资产库存于会话元数据(已持久化)的引用字段,不另造存储——**若后端无法支持,此 tab 显示 EmptyState 而非假数据**
- 空态文案:「还没有沉淀的研究成果——完成一次投研会或导出对话后,这里会成为你的研究档案室」

### 5.6 B3 运行信息(右列,可折叠)

## 6. 思维链与可信度规范

### 6.1 四阶段进度器(消费真实事件)

```
[规划 Plan]──[调用工具 Tool]──[核验 Verify]──[输出 Output]
```

| 阶段 | 驱动事件 | 视觉 |
|:---|:---|:---|
| Plan | `reasoning_chunk` 流(现在被丢弃,P0-4) | 紫色呼吸点 + 可展开的推理片段(默认折叠,标"推理过程") |
| Tool | `tool_start` → running 转圈;`tool_result` → done 勾 | 工具 chip:名称+参数摘要,展开看原始结果 JSON |
| Verify | 第二次同类 tool 调用 / `</think>` 标记(`chat-context.tsx:299-301`) | 阶段条推进,Verify 点亮 |
| Output | 首个 `text_chunk` | 正文流式渲染,进度器收起为头部细条 |

`heartbeat` 驱动"仍在连接"呼吸动画;超过 30s 无任何事件 → amber「响应缓慢,后端可能排队」,不转假圈。

### 6.2 数字可信

- 助手消息中所有数字来自 tool_result(宪法 §5);工具失败的消息必须带红色失败块「数据获取失败:{原因},以下结论不含该项数据」——禁止估计值兜底
- 工具结果卡显示取数时间戳;超 5 分钟(行情类)/ 1 日(基本面类)加 STALE 角标(`text-amber-500` + 区域 `opacity-60 saturate-50`)

### 6.3 实盘闸门

- `strategy_code` 永远先落 SANDBOX 卡;任何"部署/下单"按钮点击后先弹 REAL_TRADE_EXECUTE 状态确认(与策略研发工作台、高频回测引擎同一闸门组件)
- 交易执行类工具(manage_broker_orders_and_account)的任何调用在工具记录里标红边
