## 智能量化选股(Agentic Screener)· UI 重构设计

> 目标:把"自然语言一句话 → 可解释的规则 → 可信的结果"做成一条顺的动线,补齐状态体系,去掉数据展示层的脏点。
> 范围:纯 UI/UE 设计,不改代码;设计 tokens 与《数据中心与宏观 · Figma 导入稿》一致(bg #0F0F14 / panel #16181F / up #34D399 / down #F87171 / warn #FBBF24 / ai #A78BFA / blue #60A5FA)。
> 配套 Figma 稿:《智能量化选股_Figma导入稿.html》(2 帧)。
> 日期:2026-08-20 · 代码落点基于 quant_agent 仓库现状

---

### 一、现状诊断(基于截图)

1. **伪重复行。** 结果表里 `688729.SH/.SZ`、`688777.SH/.SZ` 以完全相同的数据各出现一次——同一标的挂两个市场后缀形成伪重复;630 条结果里此类重复无标注、无归并,条数本身被放大。
2. **原始字段泄漏。** 表头出现 `revenue_growth_fmt` 这样的后端原始 key 列,内容与前一列"营业额增长率"完全重复——前端在直接渲染接口字段而非映射后的展示列。
3. **列序不合扫读习惯。** 最新价、涨跌幅被排在市净率/市盈率之后;扫读顺序应是 价格 → 涨跌 → 规模 → 估值 → 成长。
4. **规则解析一锤子买卖。** AGENT 解析出的过滤规则只是只读 tag:想把"市盈率 ≥100"改成"≥80"只能重新打字,解析结果不可编辑、不可追加条件。
5. **状态体系缺失。** WS 断连只是底部一个红点,结果表无 STALE 标注、无数据源徽章、无更新时间;"全市场 5,832 只 · 毫秒级扫描"是营销话术,不是状态信息。
6. **大体量无方案。** 630 行裸 table 直出;筛选结果很容易破千,而编码宪法规定 >1000 行必须 AG Grid + 虚拟滚动。
7. **AI 洞察无落点。** "AI 一键洞察"只是一行提示文字,没有固定面板承载生成结果。
8. **SANDBOX 提示偏弱。** 宪法要求 UI 显示 SANDBOX/LIVE 横幅;目前仅顶栏模式胶囊 + 底部状态栏,页面主体内无说明。

### 二、重构后布局:三层动线

```
┌────────────────────────────────────────────────────────────────┐
│ 智能量化选股 AGENTIC SCREENER        [SANDBOX · 单次推演] [历史] │
├────────────────────────────────────────────────────────────────┤
│ ① 提问层                                                        │
│ ┌ 输入框:市盈率超百倍,但营收出现负增长的刺破泡沫股 ─ [生成策略]┐ │
│ └ 示例 chips:高股息低波动 / 净利连增3季 / 52周新高+放量 ────────┘ │
├────────────────────────────────────────────────────────────────┤
│ ② 透明层(左 RAG 召回依据 | 右 可编辑解析规则)                   │
│ · 知识库/研报引用(带相关度) · 规则 chips 可删/可改值/+加条件     │
│ · 置信度 + 耗时 · [订阅策略][▸ 查看源码(折叠)]                   │
├────────────────────────────────────────────────────────────────┤
│ ③ 结果层                                                        │
│ [筛选结果 630][CEP 异动]  归并同名多市场 ✓  [AI 一键洞察]  排序▾ │
│ ┌ AI 洞察卡(紫)[AI 生成 · 仅供参考]:主线概念 + 龙头点评 ────────┐ │
│ ├ AG Grid: # 代码 名称 最新价 涨跌 行业 市值 成交额 PE PB 成长 换手 ┤ │
│ └ 数据源 badge · 更新时间 · 分页 50/页                            ┘ │
│ 行点击 → /market/:ticker → 个股工作台                            │
└────────────────────────────────────────────────────────────────┘
```

设计原则沿用宏观面板四条:按任务分层(一页一问:这句话筛出了什么)、透明先于结果(先看到规则再看到表)、状态先于数字(STALE/空态/错误卡)、摘要可下钻(洞察卡 → 行 → 个股工作台)。

### 三、分区详细设计

**① 提问层**

- 输入框保留自然语言;右侧主按钮"生成策略"(蓝色主按钮),回车同义。
- 输入框下方挂示例 chips(点击即填入):高股息低波动 / 净利连增 3 季 / 52 周新高+放量 / 高 PE 负增长泡沫股——降低冷启动门槛。
- 历史记录从顶栏按钮改为输入框右上角的图标按钮,点击展开历史查询(可一键重放)。

**② 透明层(本次重构的重点)**

左卡 · RAG 召回依据:列出支撑解析的知识条目(知识库条目/研报),每条带来源类型徽章与相关度分数,最多显示 3 条,"查看全部"折叠。目的:让用户知道"为什么 AGENT 这么理解我这句话"。

右卡 · 解析规则(可编辑):
- 每个条件渲染为一枚 chip:`市场: 美股 港股 沪股 深股 ×`、`市盈率 TTM ≥ 100`、`营业额增长率(最新) ≤ 0%`。
- chip 上的**数值可点击就地编辑**(inline number input),条件尾部的 `×` 删除该条件,虚线 `+ 添加条件` 追加手工条件。
- 任一修改 → 触发重新查询,按钮进入 loading,无需重新打字。这是把"解析"从一次性展示升级为可交互对象的关键。
- 卡底部:置信度徽章(高/中/低)+ Hermes ReAct 解析耗时;`订阅策略`(次要按钮)、`查看源码` 折叠区(展示过滤引擎生成的 DSL/代码片段,只读,等宽字体深色块)。

**③ 结果层**

- tabs:`筛选结果`(计数徽章)| `CEP 异动`(保留现状)。
- **归并开关**(默认开):同名多市场伪重复按主体归并为一行,行上挂小徽章标注覆盖的市场(如"沪/深");开关旁显示"已归并 118 条重复"。归并在展示层完成,不改数据源;后端重复来源另立排查项,不阻塞本设计。
- 表格列(清理后 12 列):# / 代码 / 名称 / **最新价 / 涨跌幅**(提前)/ 行业 / 市值 / 平均成交额 / 市盈率 TTM / 市净率 / 营业额增长率 / 换手率。`revenue_growth_fmt` 列删除(前端字段映射修正)。
- 渲染:AG Grid + 虚拟滚动(结果可破千,宪法硬要求),斑马纹深色行、右对齐数值列、涨跌徽章着色。
- 行点击 → `/market/:ticker` → 个股工作台(复用现成深链机制),行尾显示 hover 提示"在工作台打开"。
- 分页 50/页 + 总数;表尾固定 DataSourceBadge(数据源:facade · screener-engine · RAG)+ 更新时间。

**AI 一键洞察**

- 固定为结果表上方的紫色卡片(`ai-card` 规范):`[AI 生成 · 仅供参考]` 徽章必挂。
- 内容三段:主线概念(行业分布 chips,如 半导体设备 214 只)、结构特征(市值/估值中位数一句话)、龙头点评(2–3 只,各一句,带涨跌徽章)。
- 数字类结论必须由 Hermes Tool 取数生成,失败时卡片显示错误态与重试,禁止编数(宪法 §5)。
- 卡片可折叠为一行按钮态,给结果表让位。

### 四、状态规范

| 状态 | 呈现 |
|---|---|
| SANDBOX | 页头琥珀胶囊"_SANDBOX · 单次推演,无持久账本_";订阅策略仅入纸面。切 LIVE 必须先通过 `REAL_TRADE_EXECUTE` 校验,横幅转红 |
| WS 断连 / 数据过期 | 结果卡右上角 STALE 琥珀标签 + 区域 `opacity-60 saturate-50` + 说明"行情快照可能滞后,展示为最后一次成功数据";禁止无标注展示过期数 |
| 空结果 | EmptyState:"没有满足条件的标的",附可点击的放宽建议按钮(如"市盈率放宽到 ≥80""市场扩到美股")——直接改规则重查 |
| 查询失败 | 错误卡(错误码 + 原因 + 重试按钮),禁止内联红字;解析失败与筛选引擎失败分开文案 |
| 解析中 / 查询中 | 透明层骨架 + 结果表 loading 遮罩,按钮转 loading,禁止旧结果与新状态混排 |

### 五、实施要点(设计层)

1. 表头字段映射修正:删除 `revenue_growth_fmt` 等原始 key 列,统一走展示列配置(列 = 显示名 + 格式化器 + 对齐)。
2. 表格换 AG Grid(虚拟滚动 + 列配置 + 行点击);结果 >1000 行是常态场景。
3. 规则 chips 组件化:条件 = `{field, op, value, editable}`;编辑/删除/追加统一走"重查"入口。
4. AI 洞察卡接入 Hermes 既有 SSE 思维链展示(生成过程可见),完成态落卡。
5. 归并逻辑放前端展示层(按名称+市值聚类归并,标注市场);后端 SH/SZ 双行来源立数据排查工单,不阻塞。
6. 复用 `EmptyState` / `DataSourceBadge` / STALE 规范组件,不新造。

### 六、验收清单

- [ ] 表头无任何原始 key 列(`revenue_growth_fmt` 消失);列序为 价格→涨跌→规模→估值→成长
- [ ] 同名多市场伪重复默认归并且有标注,总数随之修正
- [ ] 规则 chip 可编辑数值、可删除、可追加,修改即重查,无需重新输入自然语言
- [ ] AI 洞察卡固定可见,带"AI 生成 · 仅供参考"徽章;失败显示错误态而非编数
- [ ] WS 断连时结果区 STALE 标注 + 降饱和,不再只是底部红点
- [ ] 空结果有放宽建议按钮;查询失败走错误卡 + 重试
- [ ] >1000 行结果走 AG Grid 虚拟滚动不卡顿;行点击直达个股工作台
- [ ] SANDBOX 横幅在页头可见;LIVE 切换有 `REAL_TRADE_EXECUTE` 校验提示
