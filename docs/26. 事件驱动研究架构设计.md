## 一、目标与对标

### 1.1 要解决的问题

系统已沉淀大量**事件数据**（财经日历 `macro_calendar_service`、财报日历 `GET /earnings`、分红/IPO `routers/calendars.py`），但只用于「提醒」；业界价值在「规律」：事件前后的统计性收益模式是可回测、可策略化的。

| 能力 | 方法学 | 交付 |
|:---|:---|:---|
| 事件窗口研究 | 事件时间对齐 → 异常收益 → 截面平均（CAR/CAAR） | 事件类型 × 股票池 × 窗口的统计报告 |
| 公告漂移 (PEAD) | 超预期度（SUE）分位 × 后续 60 日漂移 | 漂移强度与持续期统计 |
| 持仓事件暴露 | 日历前向扫描 × 持仓交集 | 未来 N 日风险事件时间轴 + 告警 |
| 事件策略模板 | 统计结论 → 策略代码骨架 | 流转 §四 策略实验室 |

### 1.2 非目标

- 不做盘中事件实时触发交易（事件 → 告警 → 人决策）
- 不做 NLP 事件抽取（事件全部来自结构化日历源）
- 事件样本不足（< 30）时只出样本明细，不出统计结论

## 二、数据流与后端模块

```
事件源                                      研究层                           消费层
macro_calendar_service ──┐
GET /earnings（财报+预期）──┼──→ EventRegistry（标准化事件表）
calendars dividends/ipos ─┘         │
                                     ↓
快照行情（SnapshotReader，docs/19）──→ EventStudyEngine ──→ event_study_results (PG)
  (事件窗口内日收益 + 基准)               │                    ↓
                                     PEAD 分析（SUE 分位）   routers/event_study.py
                                     持仓暴露扫描（定时）──→ §十 告警（docs/18 P2）
```

| 模块 | 路径（新建） | 职责 |
|:---|:---|:---|
| 事件归一 | `backend/services/event_study/registry.py` | 各日历源 → 统一 `EventRecord`（类型/日期/标的/来源/快照） |
| 研究引擎 | `backend/domain/event_study/engine.py` | 事件时间对齐、异常收益（市场调整/行业调整）、CAR/CAAR + bootstrap 置信带 |
| PEAD | `backend/domain/event_study/pead.py` | SUE 计算（实际−预期，用 `EarningsExpectation`）+ 分位漂移 |
| 暴露扫描 | `backend/services/event_study/exposure.py` | 持仓/纸面组合 × 未来 N 日事件；高危事件（影响级别高 + 仓位 > 阈值）发告警 |
| 路由 | `backend/routers/event_study.py` | §四端点 |

**数据约束**：窗口行情一律绑定 `data_snapshot_id`；事件日期必须来自已入库事件（禁前端传入任意日期伪造样本）；外部数据经 Facade / `DataSourceRegistry`。

## 三、Pydantic Schema 草案

```python
class EventRecord(BaseModel):
    event_id: str
    event_type: Literal["earnings", "dividend", "ipo", "macro_release", "lockup"]
    symbol: str | None                        # 宏观事件为 None
    event_date: date
    source: str                               # "earnings_calendar" / "macro_calendar" / ...
    severity: Literal["low", "medium", "high"]
    payload: dict[str, Any]                   # 预期值/前值等源数据

class EventStudyRequest(BaseModel):
    event_type: str
    universe: str
    window: tuple[int, int]                   # 如 (-10, +10)
    data_snapshot_id: str
    adjustment: Literal["market", "industry", "none"] = "market"
    min_samples: int = 30

class EventStudyReport(BaseModel):
    request: EventStudyRequest
    sample_count: int
    sufficient: bool                          # < min_samples 时统计结论置空并明示
    car_curve: list[float]                    # 窗口内逐日平均异常收益
    caar_curve: list[float]
    ci_band: list[tuple[float, float]]        # bootstrap 95% 置信带
    samples: list[EventSampleRow]             # 标的/日期/超预期度/窗口收益（AG Grid 数据源）
    events_trace: list[str]                   # 溯源：事件来源与快照

class PeaDReport(BaseModel):
    sue_quantiles: dict[int, float]           # 分位 → 后续 60 日平均漂移
    drift_half_life_days: float | None

class ExposureScan(BaseModel):
    portfolio_id: str | None                  # None = 当前 OMS 持仓
    horizon_days: int = 14
    items: list[ExposureItem]                 # 日期/事件/持仓权重/严重度
    alerts_emitted: int
```

## 四、API 端点（`routers/event_study.py`）

| 方法 | 路径 | 说明 |
|:---|:---|:---|
| `POST` | `/event-study/run` | 事件窗口研究（异步 `job_id`） |
| `GET` | `/event-study/report/{job_id}` | `EventStudyReport` |
| `POST` | `/event-study/pead` | 公告漂移分析 |
| `GET` | `/event-study/exposure?horizon_days=14` | `ExposureScan`（持仓事件暴露） |
| `POST` | `/event-study/to-strategy` | 统计结论生成策略草稿（流转 §四，仅草稿不部署） |

## 七、验收标准

| 维度 | 指标 | 验收线 |
|:---|:---|:---|
| 性能 | 500 事件 × ±10 日窗口 | < 30s |
| 正确性 | CAR 与手工抽样对照 | 误差 < 1e-9（Pytest golden） |
| 诚实性 | 样本 < 30 | 结论置空 + 明示，不静默 |
| 溯源 | 每条结论 | 附事件来源 + 快照，可一键复核 |
| 时效 | 持仓暴露扫描 | 随日历数据更新 < 5min |
| 测试 | 覆盖率 | ≥ 80%（CI 门禁） |
