## 一、目标与对标

### 1.1 要解决的问题

现状：§二十一 已具备因子**生产**能力（Alpha158 计算 + LLM 建议 + 网格搜索），但因子好坏只能靠网格搜索的单策略收益间接判断——缺业界标准的因子**验证**方法学：

| 缺口 | 业界方案 | 本平台交付 |
|:---|:---|:---|
| 因子预测力无量化 | Alphalens IC / Rank IC | 日频 IC 时序 + 累计 IC + IR |
| 无单调性验证 | 分位数组合回测 | 5 分层净值曲线族 + 多空价差 |
| 因子同质化 | 相关性矩阵 | 因子间 Rank 相关热力图 |
| 市值/行业污染 | 中性化回归 | 市值（对数市值）/行业哑变量截面回归取残差 |
| 因子无资产管理 | 因子库版本化 | `factor_registry` 表 + 血缘（表达式/参数/快照/IC 摘要） |

### 1.2 非目标

- 不做高频/分钟级因子（本期日频收盘后截面）
- 不做机器学习因子组合（留给未来 ML Pipeline）
- 不做因子实盘直连交易；因子只流经「选股器条件 / 策略代码片段」两条既有通路

## 二、数据流与后端模块

```
快照层 (docs/19)                     计算层                          存储层            展示层
datalake snapshot ──→ FactorEngine.compute_panel() ──→ factor_values (Parquet)
  (universe + K线 + 市值/行业)         │                          ↓
                                      └──→ ICAnalyzer / QuantileBacktester
                                              │
                                              ↓
                                      factor_metrics (PG)  ──→ routers/factor_lab.py ──→ 前端 §25.2 面板
                                              ↓
                                      factor_registry (PG, 版本化入库)
```

**模块落位**（遵守 AGENTS.md 架构边界：`routers/` 只校验转发，业务在 `services/`，数值在 `domain/`）：

| 模块 | 路径（新建） | 职责 |
|:---|:---|:---|
| 因子面板计算 | `backend/domain/factor_lab/panel.py` | 截面因子矩阵 `T×N`（复用 `domain/alpha158.py` 的因子实现，扩展自定义表达式求值） |
| IC 分析 | `backend/domain/factor_lab/ic.py` | 日 IC（Pearson）/ Rank IC（Spearman）对前向收益（1/5/20 日）；累计 IC、IR、胜率 |
| 分层回测 | `backend/domain/factor_lab/quantile.py` | 等权 5 分位组合逐日调仓净值；多空价差序列；换手率 |
| 中性化 | `backend/domain/factor_lab/neutralize.py` | 截面 OLS：`f ~ log_mcap + industry_dummies` 取残差 |
| 服务编排 | `backend/services/factor_lab_service.py` | 快照读取（`services/datalake/snapshot_reader.py`）→ 计算 → 落库；限流与大池任务走进程池（禁阻塞路由） |
| 路由 | `backend/routers/factor_lab.py` | 见 §四端点 |

**数据源约束**：K 线/市值/行业一律经 `SnapshotReader`（docs/19）读取指定 `data_snapshot_id`；禁止直连 `yf.Ticker()` / Futu 实时接口（AGENTS §4）。

## 三、Pydantic Schema 草案（先模型后路由，AGENTS §4）

```python
class FactorLabRequest(BaseModel):
    factor_name: str                          # alpha158 名或 registry 内因子 id
    factor_expr: str | None = None            # 自定义表达式（与 name 二选一）
    universe: str                             # "hk50" / "us_sp100" / 自选池
    data_snapshot_id: str                     # 必填，禁 live
    start_date: date
    end_date: date
    forward_periods: list[int] = [1, 5, 20]   # 前向收益窗口
    quantiles: int = 5
    neutralize: list[str] = []                # ["log_mcap", "industry"]

class ICSeries(BaseModel):
    date: date
    ic: float
    rank_ic: float
    factor_coverage: float                    # 当日有效截面占比（数据质量哨兵）

class FactorMetrics(BaseModel):
    factor_name: str
    data_snapshot_id: str
    mean_ic: dict[int, float]                 # period → 均值
    ic_ir: dict[int, float]
    ic_win_rate: dict[int, float]
    quantile_returns: dict[int, float]        # 分层年化（等权，费前）
    long_short_sharpe: float
    avg_turnover: float
    computed_at: datetime

class FactorRegistryEntry(BaseModel):
    factor_id: str                            # uuid
    name: str
    version: int
    expr_or_source: str                       # alpha158 名 / 表达式
    params: dict[str, Any]
    data_snapshot_id: str                     # 入库时验证所用快照
    metrics_digest: dict[str, float]          # mean_ic_1d / ir / ls_sharpe 摘要
    created_at: datetime
    lineage: str                              # 来源：manual / llm-suggest / grid-search

class FactorLabReport(BaseModel):
    """GET /factor-lab/report 完整响应"""
    request: FactorLabRequest
    ic_series: list[ICSeries]
    quantile_nav: dict[int, list[float]]      # 分层净值曲线族
    long_short_nav: list[float]
    factor_corr: dict[str, float]             # 与 registry 内 top 因子的 rank 相关
    metrics: FactorMetrics
    reproducible: bool = True                 # 快照绑定恒真，异常时显式置假并附 reason
```

**存储**：`factor_values` 面板走 Parquet（`data/snapshots/factor_lab/`，复用数据湖目录约定）；`factor_registry` 与 `factor_metrics` 走 PG（Alembic 迁移）。

## 四、API 端点（`routers/factor_lab.py`，统一 `{status, message, data, timestamp}`）

| 方法 | 路径 | 说明 |
|:---|:---|:---|
| `POST` | `/factor-lab/analyze` | 全链路分析（IC + 分层 + 相关性），异步任务返回 `job_id` |
| `GET` | `/factor-lab/report/{job_id}` | 拉取 `FactorLabReport` |
| `POST` | `/factor-lab/registry` | 因子入库（须附 metrics_digest，版本自增） |
| `GET` | `/factor-lab/registry` | 因子库列表（可按 IC/IR 排序） |
| `GET` | `/factor-lab/registry/{factor_id}/lineage` | 血缘详情 |

错误带 `error_code`（如 `factor_snapshot_not_found` / `factor_universe_too_small`）。

## 七、验收标准

| 维度 | 指标 | 验收线 |
|:---|:---|:---|
| 正确性 | IC 与手工/Alphalens 抽样对照 | 误差 < 1e-6（Pytest golden） |
| 性能 | 50 标的 × 250 日全链路 | < 60s |
| 可复现 | 同快照 + 同因子重复运行 | 结果逐字节一致（metrics 哈希比对） |
| 数据质量 | 截面覆盖率 < 50% 的日期 | 报告显式标注并剔除，不静默 |
| 测试 | 后端覆盖率 | ≥ 80%（CI 门禁） |
| 红线 | 禁 live 数据出结论 / 禁路由层写业务 | 代码评审核对 |
