## 一、目标与对标

### 1.1 核心命题

「回测收益 ≠ 实盘收益」的差额来自：滑点模型失真、信号到下单延迟、部分成交/拒单、算法委托切片损失。TCA 的职责是把这笔账**逐笔算清、按层归因、反向哺参数**。

### 1.2 三层账本对齐模型

| 层 | 成交来源 | 语义 | 关联键 |
|:---|:---|:---|:---|
| L1 回测 | 同构引擎撮合明细（`docs/15`） | 理想执行（给定滑点模型） | `strategy_version_id` + `data_snapshot_id` + 信号 |
| L2 纸面 | `paper_fills`（docs/17 唯一成交 SSOT） | 模拟撮合（按当时行情快照） | `strategy_version_id` + 信号时间 |
| L3 实盘 | OMS 成交记录（`REAL_TRADE_EXECUTE` 闸门后） | 真实执行 | `strategy_version_id` + 信号时间 |

三层以 **信号事件**（`signal_id`：策略版本 + 标的 + 信号时刻 + 方向）为主键对齐；无 `signal_id` 的历史成交标 `unmatched`，对齐率作为健康指标上报。

### 1.3 指标定义

| 指标 | 定义 |
|:---|:---|
| 实施缺口 IS | `(成交价 − 信号价) / 信号价 × 方向符号`，买入为正为成本 |
| 三段分解 | 信号价→决策价（延迟滑点）→提交价（决策滑点）→成交价（市场冲击），逐段归因 |
| 机会成本 | 未成交数量 × (窗口末价 − 信号价)，按约定窗口（默认 20 分钟） |
| 层间偏差 | `NAV_L3 − NAV_L2 − NAV_L1` 的逐日差分序列 + 累计偏差 |
| 算法委托评分 | TWAP/VWAP：参与率、价格改进、切片完成度 |

## 二、数据流与后端模块

```
L1 回测成交 (backtest trades) ─┐
L2 paper_fills (PG)          ─┼──→ SignalAligner（signal_id 对齐）──→ tca_fills (PG 派生表)
L3 OMS 成交 (PG)             ─┘              │
                                              ↓
行情快照（信号时刻盘口/最新价，经 DataSourceRegistry，docs/14）
                                              ↓
                                    TcaCalculator（IS/分解/成本）──→ tca_metrics (PG)
                                              ↓
                                    routers/tca.py ──→ OMS「执行质量」Tab
                                              ↓（反向哺）
                          回测参数区滑点默认值（实测中位滑点，人工确认后写入）
```

| 模块 | 路径（新建） | 职责 |
|:---|:---|:---|
| 信号对齐 | `backend/services/tca/aligner.py` | 三层成交按 `signal_id` 对齐；容错窗口（默认 ±5s，可配） |
| 指标计算 | `backend/domain/tca/metrics.py` | IS/三段分解/机会成本/层间偏差（纯函数，可单测） |
| 服务 | `backend/services/tca/service.py` | 编排 + 增量计算（新成交触发，禁全量重算） |
| 路由 | `backend/routers/tca.py` | §四端点 |

**红线**：只读真实成交与真实行情；严禁注入模拟滑点数据冒充实测（AGENTS §4 禁假数据）。实盘相关查询必须感知 `REAL_TRADE_EXECUTE` 状态，未开启时 L3 层显式置空并返回 `layer_unavailable`。

## 三、Pydantic Schema 草案

```python
class TcaFillPair(BaseModel):
    signal_id: str
    symbol: str
    side: Literal["buy", "sell"]
    signal_time: datetime
    signal_price: float
    decision_price: float | None
    submit_price: float | None
    fill_price: float | None
    fill_qty: float
    signal_qty: float
    implementation_shortfall_bps: float | None
    latency_ms: int | None
    layer: Literal["backtest", "paper", "live"]
    attribution: str | None                  # "delay" / "market_impact" / "partial_fill" ...

class TcaSummary(BaseModel):
    strategy_version_id: str
    period: tuple[date, date]
    layers_available: list[str]
    median_is_bps: dict[str, float]          # layer → 中位 IS
    p95_is_bps: dict[str, float]
    opportunity_cost_total: float
    nav_gap_cum: dict[str, float]            # "L2-L1" / "L3-L2" 累计偏差
    align_rate: float                        # 三层对齐率
    algo_stats: dict[str, Any] | None        # TWAP/VWAP 评估

class TcaReport(BaseModel):
    summary: TcaSummary
    fill_pairs: list[TcaFillPair]            # 分页
    slippage_hist: dict[str, list[int]]      # 买卖分列直方图桶
    suggested_backtest_slippage_bps: float   # 反向哺：实测中位滑点建议值
```

**存储**：`tca_fills` / `tca_metrics` PG 派生表（Alembic 迁移）；行情快照读取走 `DataSourceRegistry.fetch`，缓存于 Redis（TTL 与现有一致）。

## 四、API 端点（`routers/tca.py`，统一响应包 + `error_code`）

| 方法 | 路径 | 说明 |
|:---|:---|:---|
| `GET` | `/tca/summary?strategy_version_id=&days=30` | `TcaSummary` |
| `GET` | `/tca/fills?...&page=` | 逐笔偏差表（分页） |

## 七、验收标准

| 维度 | 指标 | 验收线 |
|:---|:---|:---|
| 对齐 | 三层成交对齐率 | ≥ 99%（`unmatched` 列表可查） |
| 正确性 | IS 计算与手工样例对照 | 逐笔一致（Pytest golden） |
| 性能 | 增量计算单笔 | < 200ms；日报表 < 2s |
| 诚实性 | 无实盘/无纸面数据 | 对应层显式缺省说明，禁假数据 |
| 闭环 | 实测滑点 → 回测默认参数 | 一键应用且留审计记录 |
| 测试 | 覆盖率 | ≥ 80%（CI 门禁） |
